## Mutation interpretation and final limits

`mutations.json` contains exact edits, commands, raw and normalized log hashes, intended assertion outcomes and source identities. `payload-recovery-barrier` initially survived the ordinary actual commit-observer test because successful commit disarmed cleanup before run's result check. This is a **test-path-limited survivor**, not a redundant production guard: the same deletion is killed by actual TEST1162's ambiguous AfterCommit cleanup, where the retained sealed slot is wrongly deleted. Both outcomes remain recorded. Other guard failures are behavioral; type checks are separately identified compile-fail evidence, never counted as executed runtime tests.

Some session mutation runs precede only the later cfg(test) entered-count accessor. The exact removable accessor delta and reconstructed source hashes are recorded in verification.json; they are not labelled final-byte-identical. Formatting/test-lint repairs and the read fixture's closed-peer handling are likewise source-accounted; the final blocking-read mutant was rerun against its final fixture. No unrelated compilation failure counts as a kill.

The exact test commands/results are in `prior-independent-tests.json`, `final-independent-tests.json`, and `author-transition-tests.json`; their independent attribution and prior/final source identities remain explicit. The final independent review, dependency-closure build, exact native/served-browser depth and remote CI remain root-owned acceptance evidence. This change neither resets those gates nor claims production rollout, camera hardware testing, or broad assurance beyond the named contracts.
